What this is, and how to run it

GUIde is a local inbox for the questions your agents need answered. An agent writes a JSON file of judgment calls with the evidence attached, pushes it to a daemon on your machine, and a browser page renders it as cards with buttons. You click through them. The answers land back on disk as JSON and the agent picks up where it left off.

runs on: 127.0.0.1 language: Python 3.11+ dependencies: three build step: none accounts: none

The one idea

The UI is a pure function of a JSON file. Everything else — the format, the daemon, the CLI, the skill — exists to get a batch into that function and answers back out. 

render(batch)  -> a page of cards
collect(page)  -> answers

The corollary matters as much: the renderer never learns your domain. It does not know what a "verifier check" or a "regression case" is. Domain data rides along in an opaque meta object that is passed through untouched and echoed back in the answers. That single rule is what stops GUIde from slowly becoming specific to one project.

Four words, used consistently everywhere

TermWhat it is
batchOne JSON file — a list of questions an agent wants answered, with evidence
cardOne question in that batch, as drawn on screen: title, evidence, buttons
answersThe JSON file that comes back out when you're done
inboxEvery batch currently waiting on you, across all your sessions

Running it

The toolchain is uv. It is a single static binary that manages its own Python — it does not touch a system Python, a Homebrew Python, or an existing pyenv.

From a clone, for development

# installs uv into ~/.local/bin, and nothing else, anywhere
curl -LsSf https://astral.sh/uv/install.sh | sh

cd GUIde
uv sync                 # creates ./.venv with a managed Python 3.12
uv run guide status     # is anything running, and what's waiting
uv run pytest           # 196 tests
uv run ruff check src tests

As a tool you actually use

uv tool install --from . guide-cli    # from a clone; not on PyPI yet
guide status

uv tool install puts guide on your PATH in its own isolated environment. uvx --from . guide status runs it without installing anything at all.

The loop, in four commands

guide push ./questions.json   # starts the daemon if it isn't running
guide list                    # what's waiting, across every session
guide open                    # the inbox, in a browser
guide wait <id>               # blocks until you press Done, then prints the answers

Teaching Claude to use it. Run guide skill install, or open http://127.0.0.1:7777/skill — the daemon serves an install page with four paths, including a prompt you can paste into any Claude Code session to have it install the skill itself. The page knows which SKILL.md matches your installed build, so its instructions cannot go stale.

Everything runs on your machine

Batches will contain real data. The local-only model handles that by construction rather than by policy — nothing is transmitted, because there is nothing to transmit to:

bound to loopback

127.0.0.1, never 0.0.0.0

There is no auth because there is nobody else on the socket.

enforced by header

No outbound requests

A Content-Security-Policy of default-src 'none' means the page cannot load a CDN, a font, or an analytics script even if someone adds one.

outside every repo

Batches live in ~/.guide/

So they cannot be accidentally committed. Structural, not a .gitignore line someone forgets to copy.

always

Nothing in examples/ is real

Synthetic data only, in every example and every test fixture.
